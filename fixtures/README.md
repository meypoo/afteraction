# Fixtures

Anonymized sample logs for adapter tests. No real log content is committed here.

## How they were made

`claude-code/projects/…` was generated from real Claude Code logs by a script that keeps the JSON
structure and enum-like values (`type`, `subtype`, `model`, `version`, `stop_reason`, tool names,
token counts) and replaces everything else:

- free text (prompts, replies, tool output, file contents, titles) → `<key placeholder, N chars>`
- ids (`uuid`, `toolu_…`, `msg_…`, `req_…`, agent ids) → deterministic fake ids, consistently remapped so
  `parentUuid`, `tool_use_id`, `sourceToolAssistantUUID` and repeated `message.id` links still hold
- file paths → `C:\Users\USER\projects\demo-app\src\fileN.ext`
- shell commands → harmless placeholders (`npm test`, `git status`, …)
- timestamps → rebased to 2026-01-15
- MCP tool names other than `mcp__playwright__*` → `mcp__example__tool_N`
- `parentUuid` rewritten into a linear chain, because lines were sampled from several sessions

The output was then checked against the real logs: no real uuid or tool/message id appears, and no
string outside the placeholder patterns remains.

### `codex/`

Hand-written, modeled on real Codex Desktop rollouts (same keys and record order) and on Codex's
open-source rollout schema for CLI-only shapes. No real log content. Layout mirrors `~/.codex`.

- `sessions/2026/01/15/rollout-…-0198a1b2-c3d4-….jsonl`: Codex CLI. Injected `<environment_context>`,
  reasoning summary, `shell` function calls with `exec_command_end` (exit 0 and exit 1, JSON and plain-text
  outputs), `apply_patch` adding, updating and deleting files, `update_plan`, a web search, repeated
  `token_count` with unchanged totals, and an aborted turn.
- `sessions/2026/01/16/rollout-…-0198a1b2-d4e5-….jsonl`: Codex Desktop. `content_item_kinds`, encrypted
  reasoning, `exec` scripts whose `FileChange` / `CommandExecution` items replace them (one recursive
  delete for the risk rules), an `exec` script with no command, `token_usage_record` usage.
- `archived_sessions/rollout-…-0198a1b2-e5f6-….jsonl`: a Desktop import of another agent's session
  (`external-import-turn-1`). Expected: no session, no events, no warnings.
- `legacy/…`: pre-envelope rollout (bare meta line, `record_type: state`, `local_shell_call`).
- `malformed/…`: line 3 cut off, 4 blank, 5 array, 6 not JSON, 7 unknown line type, 8 unknown response
  item, 9–10 the same unknown `event_msg` twice (one warning), 11 orphan output with an invalid
  timestamp, 13 truncated last line without a newline.

Generated by a small script kept out of the repo; edit the files directly if they need to change.

Expected normalized snapshots will be added next to these files with the adapter tests.

### `antigravity/`

Mirrors `~/.gemini/antigravity/`. Hand-built from the shapes in real Antigravity data (2026-09); every
id, path, title and text is synthetic (`aaaaaaaa-…-00000000000N` uuids, `c:\Users\USER\projects\demo-app`).

- `agyhub_summaries_proto.pb`: protobuf with summaries for conversations 1 and 2, plus one entry with
  no summary.
- `conversations/<uuid>.pb`: opaque bytes standing in for the encrypted conversation files.
- `brain/…0001/.system_generated/logs/transcript.jsonl`: every step type and tool seen in the real log,
  a failed and a successful command, a background command, edit diffs, an artifact write, an error
  and an unknown step type (last line). `expected/…0001.json` is its normalized snapshot.
- `brain/…0002/`: metadata-only conversation (task and plan documents with `.metadata.json`).
- `malformed/brain/…0003/…/transcript.jsonl`: by line, 1 prompt, 2 truncated JSON, 3 blank, 4 array,
  5 not JSON, 6 orphan result, 7 unencoded argument + invalid timestamp + non-object tool call,
  8 unknown step type, 9 prompt without wrapper tags and no trailing newline.

### `opencode/`

- `opencode.sql`: the real OpenCode 1.19.4 `CREATE TABLE` statements for `project`, `session`,
  `message` and `part`, plus synthetic rows in the shapes of a real session. Kept as SQL because
  `*.db` is git-ignored; the tests build `opencode.db` from it in a temp folder.
  - Session `ses_fixture…0001`: prompt, text, `bash` (exit 0 and 1), `read` of a file and of a
    directory, an unmapped tool (`glob`), a `patch` part, an automatic compaction (compaction part,
    summary message, synthetic "Continue" prompt) and an empty reasoning part.
    `expected/ses_fixture…0001.json` is its normalized snapshot.
  - Session `ses_fixture…0002` (malformed): invalid and non-object message and part JSON, an unknown
    part type, a tool in `error` status, a message `error`, usage with no parts, bad times and tokens,
    an empty title.

### Unverified formats: `gemini-cli/`, `cursor/`, `copilot/`, `cline/`, `aider/`, `continue/`

Hand-written from each tool's source code (see "Unverified formats" in docs/log-formats.md), not
from real logs; replace them with anonymized real samples once sessions exist. Each folder mirrors the
tool's own layout and includes malformed or unusual cases (unknown types, non-object entries, broken
JSON, empty sessions). `cursor/*.sql` are built into `state.vscdb` files by the tests, because database
files are not committed. `expected/` holds each adapter's normalized snapshot.
